# Vps Hermes Okx Architecture

title: "Antigravity Swarm Architecture: VPS, Hermes & OKX Integration"
author: "Antigravity AI / AGENTS-OS v6.5"
type: "Deployment & System Architecture"
target_environment: "Docker / Hostinger VPS"
exchange: "OKX (USDC-Margined / Hedge Mode)"ARCHITEKTURA SYSTEMU ANTIGRAVITY (SWARM EDITION)Dokument ten definiuje docelową architekturę wdrożeniową dla bota tradingowego "antigravity" (MMS v4) uruchamianego na serwerze VPS (Hostinger) w środowisku Docker. Zakłada on współpracę z autonomicznym agentem kognitywnym Hermes (Nous Research) w modelu Agent-as-a-Client.Wszelki kod generowany przez subagenta Builder musi rygorystycznie przestrzegać poniższych założeń infrastrukturalnych, bezpieczeństwa oraz logiki biznesowej.1. MODEL "AGENT-AS-A-CLIENT" (HERMES + FASTAPI)Zamiast budować klasycznego bota działającego w próżni, system "antigravity" operuje jako zestaw narzędzi (Tools) dla autonomicznego agenta Hermes.Warstwa Egzekucyjna (Antigravity Core): Aplikacja w Pythonie używająca biblioteki ccxt.async_support do bezpośredniej komunikacji z OKX. Zawiera twardą Maszynę Stanów (MMS4StateManager).Warstwa Komunikacyjna (FastAPI): Pythonowy rdzeń jest obudowany w serwer webowy FastAPI. Wystawia on lokalne endpointy REST.Warstwa Orkiestracji (Hermes): Agent Hermes (posiadający zdolność Function Calling) komunikuje się z bazą poprzez zdefiniowane endpointy, wydając polecenia i pobierając stan rynku oraz logi.2. INFRASTRUKTURA DOCKER I BEZPIECZEŃSTWO (R-SEC-01)Zgodnie z protokołem AGENTS-OS v6.5, środowisko na VPS musi być w pełni wyizolowane i odporne na halucynacje agentów.Sieć (Docker Network): Kontenery antigravity (FastAPI) oraz hermes muszą znajdować się w jednej wewnętrznej sieci internal_swarm_net. Żadne porty interfejsu handlowego nie są wystawiane na świat (host port mapping jest zablokowany).Zarządzanie Sekretami (R-SEC-01): Klucze API OKX (OKX_API_KEY, OKX_SECRET, OKX_PASSPHRASE) są wstrzykiwane do kontenera antigravity za pomocą ukrytego pliku .env na VPS-ie. Hermes nie ma dostępu do zmiennych środowiskowych z kluczami. Operuje wyłącznie poprzez zdefiniowane endpointy FastAPI.Persystencja Danych (State Machine Memory): Katalog .agents/swarm/ z wnętrza kontenera antigravity musi być zamapowany jako docker volume na dysk fizyczny VPS. Zapobiega to utracie danych o stanie sekwencyjności (Scout Mode x0.1 vs Base x1) w przypadku restartu kontenera.3. WARSTWA EGZEKUCYJNA: INTEGRACJA OKXPodczas pisania modułu API (np. okx_executor.py), subagent Builder musi wdrożyć następujące zasady:Biblioteka: Wyłączne użycie ccxt.async_support.okx.Tryb Konta: System musi programowo zweryfikować lub wymusić tryb Hedge Mode (Dual-direction position) na koncie Futures.Waluta Rozliczeniowa (MiCA Compliance): Skrypty kalkulujące ryzyko i pozycje mają domyślnie operować na parach USDC (np. BTC-USDC-SWAP), unikając par z USDT z uwagi na ograniczenia regulacyjne w Europie.Zarządzanie Błędami Sieci: Pętla asynchroniczna musi posiadać mechanizmy try/except z logiką wykładniczego opóźnienia (exponential backoff) w przypadku zerwania połączenia WebSocket z OKX.4. API TOOLING DLA HERMESA (DEFINICJA ENDPOINTÓW)Aplikacja FastAPI musi udostępniać następujące endpointy (narzędzia) dla Hermesa, aby ten mógł realizować założenia UI/Dashboardu MMS v4:A. Endpointy Informacyjne (GET)/api/v1/state -> Zwraca aktualny stan maszyny (Base x1.0, Scout x0.1), aktywne zlecenia i przypisane im Stop Lossy./api/v1/stats/pnl -> Zwraca dzienne ROE % oraz zysk/stratę.B. Endpointy Egzekucyjne / Awaryjne (POST)/api/v1/emergency/killall -> Natychmiastowe wysłanie zlecenia close_all_positions do OKX i anulowanie otwartych zleceń Limit/Stop./api/v1/emergency/reverse -> Natychmiastowe odwrócenie pozycji (zamknięcie obecnej i otwarcie przeciwnej) z zachowaniem twardego SL=2%./api/v1/trade/high_risk_add -> Wymuszenie dokładki (lewar x1, niezależny ticket) z ciasnym SL=1% po pojawieniu się świecy potwierdzającej.5. WYTYCZNE PROJEKTOWE DLA SUBAGENTA "THE BUILDER"Maszyna Stanów (State Machine): Główna klasa MMS4StateManager musi posiadać ścisłą logikę:Uderzenie w -2% SL na bazie = przejście w State: REDUCED_RISK (x0.1).Realizacja TP w REDUCED_RISK = powrót do State: BASE (x1).Walidacja Przed-Wykonawcza (Pre-Trade Check): Zanim żądanie z endpointu FastAPI zostanie przekazane do ccxt, klasa zarządzająca ryzykiem musi sprawdzić, czy nie zostaną naruszone zasady MMS v4 (np. zablokowanie dokładek w trybie REDUCED_RISK).Format Logów: System logowania (zapisywany do wolumenu w .agents/swarm/logs.db) musi być czytelny dla modelu językowego, aby Hermes mógł łatwo analizować historię działań za pomocą operacji I/O na plikach.
