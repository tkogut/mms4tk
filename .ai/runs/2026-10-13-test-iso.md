## Goal

`tests/test_position_sizing.py::test_daemon_position_sizing_calculation` and `tests/test_max_margin_allocation.py::test_daemon_70_30_capital_split_calculation` pass again, and the intended sizing behavior is pinned by a test, **without touching production code**.

## Context (root cause, see the #109 comment)

`MMS4Daemon.plan_allocation` (`daemon.py:~326-346`) takes the per-symbol margin from `configured_symbols_store` (loaded from `symbols.json` / SQLite) and overrides the constructor's `trade_amount_usd`. The tracked `symbols.json` has `allocation_usd: 100.0` for BTC and ETH (production budget, by design), so a daemon built with `trade_amount_usd=10.0` sizes 70 USD instead of 7 USD: exactly the 10x seen in both tests (`0.000108` vs `0.00108` at 64 800; `0.00014` vs `0.0014` at 50 000). Other tests (e.g. `tests/test_allocation_ssot.py`) already clear that store with an autouse fixture; these two do not. Production is correct (status shows `margin_cap 100`, `margin_base 70`).

## Scope

1. A reusable fixture in `tests/conftest.py` that empties `configured_symbols_store` for a test and restores it afterwards (the autouse `_isolate_system_settings` already snapshots/restores; this adds the "start empty" part).
2. Apply it to the two failing test modules.
3. One new test that pins the intended behavior: with a per-symbol `allocation_usd` the daemon sizes from it, not from `trade_amount_usd`.

## Non-goals

- No change to `src/` and no version bump (nothing shipped changes; the SSOT 4-file sync is for releases).
- Not touching the other tests that already isolate the store, and not changing `symbols.json`.
- Does not modify `.agents/plans/`.

## Risks

- A fixture that clears the global store could hide a real regression if applied too widely; it is applied only to these two modules, and the new test covers the override path explicitly.
- `configured_symbols_store` is a shared module-level dict: the fixture must restore it (also on failure).
